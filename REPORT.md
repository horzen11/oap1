# Звіт до лабораторної роботи №4

## Тема
Інтеграція фронтенду з бекендом.

## Мета роботи
Сформувати практичні навички інтеграції frontend-частини вебзастосунку з backend API: виконувати HTTP-запити через `fetch()`, відображати отримані дані, обробляти стани інтерфейсу `loading / success / empty / error`, обробляти помилки 4xx/5xx, налаштовувати CORS і узгоджувати DTO-контракти.

## Використані технології

- Backend: Node.js, Express, TypeScript, SQLite.
- Frontend: Vite, TypeScript, HTML, CSS.
- Інтеграція: `fetch()`.
- Формат обміну: JSON DTO.

## Опис виконання роботи

У роботі використано проєкт попередніх лабораторних робіт. Backend залишено на Express + TypeScript + SQLite, а для ЛР4 додано окрему папку `frontend`, у якій реалізовано клієнтську частину на TypeScript.

Frontend і backend запускаються окремо. Backend працює на `http://localhost:3000`, frontend — на `http://127.0.0.1:5173`. Взаємодія між ними відбувається через HTTP API.

## Реалізовані endpoints

Для основної сутності `Requests` використано такі endpoints:

```http
GET /api/v1/requests
GET /api/v1/requests/:id
POST /api/v1/requests
PUT /api/v1/requests/:id
DELETE /api/v1/requests/:id
```

Також використовується endpoint для отримання користувачів:

```http
GET /api/v1/users
```

## Frontend-інтеграція

У frontend реалізовано:

- завантаження списку заявок з backend;
- перегляд деталей заявки;
- створення нової заявки;
- редагування заявки;
- видалення заявки;
- пошук по заявках;
- показ повідомлень про успіх і помилки.

Усі запити винесено в окремий модуль:

```text
frontend/src/apiClient.ts
```

Це дозволяє не дублювати `fetch()` у різних частинах UI.

## Стани інтерфейсу

Для списку заявок реалізовано такі стани:

- `loading` — показується повідомлення «Завантаження...»;
- `success` — дані успішно отримано і показано в таблиці;
- `empty` — якщо backend повернув порожній список;
- `error` — якщо виникла помилка завантаження.

## Обробка помилок

Frontend обробляє:

- HTTP-помилки 400, 404, 500;
- помилки мережі;
- CORS-помилки;
- timeout запиту.

У `apiClient.ts` використано `AbortController`, який скасовує запит, якщо backend не відповідає протягом 10 секунд.

## CORS

На backend налаштовано CORS з whitelist origin. Дозволено такі адреси frontend:

```text
http://localhost:5173
http://127.0.0.1:5173
http://localhost:5500
http://127.0.0.1:5500
```

Дозволені методи:

```text
GET, POST, PUT, PATCH, DELETE, OPTIONS
```

## DTO та версійність API

API має префікс версії:

```text
/api/v1
```

На frontend створено файл з типами DTO:

```text
frontend/src/dtos.ts
```

Основні DTO:

```ts
RequestResponseDto
CreateRequestRequestDto
UserResponseDto
ApiErrorDto
```

Правила сумісності DTO:

1. У `/api/v1` не видаляти й не перейменовувати поля, які використовує frontend.
2. Нові поля додавати як необовʼязкові.
3. Несумісні зміни робити тільки через нову версію API, наприклад `/api/v2`.

## Перевірка роботи

### Перевірка запуску backend

```bash
npm run dev
```

Перевірка:

```http
GET http://localhost:3000/health
```

Очікуваний результат:

```json
{
  "ok": true
}
```

### Перевірка запуску frontend

```bash
cd frontend
npm run dev
```

Після запуску frontend відкривається у браузері за адресою:

```text
http://127.0.0.1:5173
```

### Перевірка GET

При відкритті сторінки frontend автоматично завантажує список заявок через:

```http
GET /api/v1/requests
```

### Перевірка POST

Через форму можна створити нову заявку. Після успішного створення список оновлюється автоматично.

### Перевірка PUT

Кнопка «Редагувати» заповнює форму даними заявки. Після натискання «Оновити» frontend відправляє PUT-запит.

### Перевірка DELETE

Кнопка «Видалити» відкриває підтвердження. Після підтвердження заявка видаляється, а список оновлюється.

### Перевірка 400

Якщо ввести неправильні дані, frontend показує повідомлення про помилку валідації. Backend повертає статус 400.

### Перевірка 404

Якщо звернутися до неіснуючого id, backend повертає 404, а frontend показує помилку.

### Перевірка мережевої помилки

Якщо вимкнути backend і відкрити frontend, інтерфейс не ламається, а показує повідомлення, що API недоступне.

Посилання на GitHub потрібно вставити у фінальному звіті після завантаження роботи до репозиторію.

## Висновок

У результаті виконання лабораторної роботи було інтегровано frontend з backend API. Frontend отримує, створює, оновлює і видаляє дані через HTTP-запити. Налаштовано CORS, реалізовано `apiClient`, типізовано DTO, додано обробку помилок і стани інтерфейсу. Робота відповідає вимогам рівнів «задовільно», «добре» та «відмінно».
